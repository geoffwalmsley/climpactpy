{% load i18n static ui %}{% comment %} The station workspace's header (#179, #197): the station's name, a line with the file, its years and base period (changed in the Inputs panel beside the section, #198), the page's actions, then the section tabs. It stays in view as the page scrolls (sticky), so it must be a direct child of the page's .station-page; the page's scroll-padding keeps a focused element out from under it (WCAG 2.4.11), kept to the header's height by js/workspace.js. On phones (#203, proposal 7) the name and the ⋯ menu share one line, the actions are in that menu (a
disclosure; js/workspace.js closes it on Escape and on a click elsewhere), and under the tabs the Inputs bar replaces the Inputs panel: the inputs in one line and an Edit that opens them in a sheet (stations/_inputs.html). Only the tabs and the bar stay in view as the page scrolls. On the three section pages and the first visit's details the name is the page's h1 (``heading``); on a page inside a section (an index, the sector comparison) it is a line above that page's own h1. The title is the station name the user gave, the file name when there is none yet. Context: analysis, workspace_tabs, workspace_current (stations.workspace.context), heading, actions (optional: a template with the page's actions, such as Download all), inputs and inputs_bar (stations.workspace.inputs_panel; the bar shows where the page has the Inputs panel), no_inputs_bar (a page without the panel, such as an input's own page). {% endcomment %}
